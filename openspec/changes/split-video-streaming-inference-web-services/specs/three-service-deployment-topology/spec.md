## Purpose

定义摄像头侧、GPU 节点和浏览器侧之间稳定的三个服务交付边界，让系统能够在不同硬件和网络环境中独立部署、升级和诊断，同时不改变用户获得物品位置答案的方式。

## ADDED Requirements

### Requirement: 系统提供三个可独立交付的服务
系统 MUST 提供视频推流服务、GPU 推理 API 服务和 Web 前端服务三种独立交付单元。每个单元 MUST 具有独立的构建入口、运行配置和存活/就绪检查；停止或升级其中一个单元时，其他单元不应被要求重建。

#### Scenario: 单独部署 Web 前端
- **GIVEN** GPU 推理 API 服务已在可访问地址运行
- **WHEN** 部署系统仅构建并启动 Web 前端服务
- **THEN** 浏览器可以通过配置的公开 API 地址发起文字或语音物品查询，而无需部署摄像头或模型运行时

### Requirement: 视频推流服务仅承担采集与受控帧传输
视频推流服务 MUST 从一个 USB、RTSP 或 mock 视频源读取帧，并以受限大小的 JPEG 帧推送至配置的 GPU 推理 API 服务。它 MUST 使用配置的认证凭据保护推送请求，MUST NOT 持久化视频、运行视觉或 ASR 模型、访问业务数据库或向浏览器提供查询 API。

#### Scenario: 摄像头侧推送最新帧
- **GIVEN** 视频推流服务已配置可读的视频源、接收地址和有效推送凭据
- **WHEN** 视频源产生新帧
- **THEN** 服务将符合大小限制的 JPEG 帧发送至 GPU 服务的受保护接收端点，且本地不创建视频归档

### Requirement: GPU 推理 API 服务封装私有运行时
GPU 推理 API 服务 MUST 在单个部署边界中提供帧接收、视觉推理、语音转写、物品查询、观测写入和证据读取能力。视觉模型、ASR 运行时、模型缓存及其诊断端点 MUST 是该服务的私有依赖，MUST NOT 作为面向 Web 或公网的独立产品服务暴露。

#### Scenario: GPU 服务处理一帧并提供查询结果
- **GIVEN** GPU 推理 API 服务及其私有运行时均处于就绪状态
- **WHEN** 服务接收一帧并随后收到 Web 发起的物品查询
- **THEN** 服务使用内部视觉运行时生成可验证观测、由 API 持久化符合证据规则的事实，并返回既有的查询结果结构

### Requirement: 服务间网络面最小化
Web 前端服务 MUST 仅调用 GPU 推理 API 服务的公开 API。视频推流服务 MUST 仅调用 GPU 服务的受保护帧接收端点。GPU 服务 MUST NOT 将内部模型或 ASR 端口暴露给 Web、推流端或公网；部署配置 MUST 能够显式区分公开地址和内部地址。

#### Scenario: Web 无法访问内部模型端口
- **GIVEN** 三个服务按生产网络配置部署
- **WHEN** Web 前端尝试访问视觉模型或 ASR 的内部地址或端口
- **THEN** 该请求不具备可路由的公开目标，而 Web 的正常查询仍可经公开 API 完成

### Requirement: 跨服务故障可区分且可恢复
三个服务 MUST 各自报告存活与就绪状态。GPU 服务不可用时，视频推流服务 MUST 报告最近推送失败而不积压视频；视频推流服务不可用时，GPU API MUST 继续返回已有的物品查询事实，并明确当前观测可能过期。

#### Scenario: GPU 服务暂时不可用
- **GIVEN** 视频推流服务正在向 GPU 服务发送帧
- **WHEN** GPU 服务的接收端点不可用或超时
- **THEN** 推流服务记录可观察的传输失败并丢弃该帧，后续恢复后继续推送，且不会形成无界帧队列
