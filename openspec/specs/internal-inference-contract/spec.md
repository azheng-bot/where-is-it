# internal-inference-contract Specification

## Purpose

定义 API、视觉编排器和模型服务之间稳定、可追踪且可降级的内部推理契约，保证模型服务可以独立演进而不影响物品查询事实的来源和可解释性。

## Requirements

### Requirement: 内部推理请求可追踪且有界
每个内部推理请求 MUST 携带稳定请求关联标识、契约版本、调用时限和输入媒体或帧引用。服务 MUST 在响应中回传关联标识、已使用模型版本和成功、降级或失败状态。

#### Scenario: 编排器调用目标定位服务
- **GIVEN** 编排器已经获得一个摄像头帧引用和请求关联标识
- **WHEN** 编排器向 Grounding 服务发起目标定位请求
- **THEN** 请求与响应都包含相同关联标识、契约版本、时限和模型版本信息

### Requirement: 推理失败不伪造观测事实
当模型服务超时、拒绝请求或返回不兼容结果时，编排器 MUST 将该结果标记为失败或降级，且 MUST NOT 将未验证的检测结果写入或上报为当前物品位置。

#### Scenario: 目标定位请求超时
- **GIVEN** 编排器已向目标定位服务发出带时限的请求
- **WHEN** 服务未在时限内返回结果
- **THEN** 编排器记录关联的超时状态，并且不向 API 上报该请求产生的未验证位置观测

### Requirement: API 是观测事实的唯一写入方
模型服务和视觉编排服务 MUST 只返回推理或归一化观测结果；只有 API 可以将满足产品证据规则的观测、证据和查询事实持久化。

#### Scenario: 模型检测到候选物品
- **GIVEN** Florence 或 Grounding 服务返回一个候选检测
- **WHEN** 编排器归一化该检测并向 API 上报
- **THEN** 候选检测不会由模型服务直接写入数据库，且 API 按既有证据规则决定是否形成可查询事实
