## Purpose

本能力用于让单个用户在响应式网页中通过文字或麦克风询问某个具体物品的位置，并在五秒目标内获得基于结构化观测事实、可语音播报且可展开证据的自然语言回答。

## ADDED Requirements

### Requirement: 解析具体物品查询
系统 MUST 理解以“我的什么东西在哪”为核心的中文自然语言查询，并将物品提及解析为唯一 `object_id`；可使用规范名称和别名匹配，但不得在多个候选之间任意选择。

#### Scenario: 唯一名称查询
- **GIVEN** 目录中存在唯一规范名称“我的黑色保温杯”
- **WHEN** 用户输入“我的黑色保温杯在哪”
- **THEN** 系统将查询解析到该物品的 `object_id`
- **AND** 返回该具体物品而非抽象“水杯”类别

#### Scenario: 类别词对应多个物品
- **GIVEN** 目录中同时存在“黑色水杯”和“白色水杯”
- **WHEN** 用户只问“我的水杯在哪”
- **THEN** 系统请求用户在两个唯一名称之间澄清
- **AND** 不得擅自返回其中一个水杯的位置

#### Scenario: 没有匹配物品
- **GIVEN** 目录中不存在与提问名称或别名匹配的物品
- **WHEN** 用户提交查询
- **THEN** 系统说明未在物品目录中找到该对象
- **AND** 提供现有相近唯一名称作为可选建议（如存在）

### Requirement: 网页文字交互
系统 MUST 在桌面和手机尺寸的网页中提供问题输入、提交、处理中、回答和错误状态，并保留本次会话的问答记录。

#### Scenario: 提交文字问题
- **GIVEN** 用户已打开查询页面且后端服务健康
- **WHEN** 用户输入问题并提交
- **THEN** 页面立即显示处理中状态
- **AND** 完成后显示自然语言回答及状态标签

### Requirement: 网页麦克风输入
系统 MUST 提供网页内嵌的麦克风按钮，将中文语音转换为可见、可编辑的提问文本，并允许用户确认或直接提交。麦克风权限被拒绝或能力不可用时 MUST 保留完整文字输入能力。

#### Scenario: 成功语音提问
- **GIVEN** 浏览器支持已配置的语音识别方式且用户授予麦克风权限
- **WHEN** 用户说“我的钥匙在哪里”并结束录音
- **THEN** 页面展示识别文本
- **AND** 用户可修改或提交该文本

#### Scenario: 麦克风权限被拒绝
- **GIVEN** 用户拒绝麦克风权限
- **WHEN** 用户尝试开始录音
- **THEN** 页面给出可理解的权限提示
- **AND** 文字查询功能继续可用

### Requirement: 文字和语音回答
系统 MUST 为成功查询生成简洁中文回答并显示文字；由语音输入触发的成功回答 MUST 自动开始语音播报，所有成功回答 MUST 提供重播和停止播报控制。

#### Scenario: 语音问题获得播报
- **GIVEN** 用户通过麦克风提交了有效物品查询
- **WHEN** 文字回答生成完成
- **THEN** 页面显示完整文字回答
- **AND** 自动播报相同核心事实

#### Scenario: 用户停止播报
- **GIVEN** 页面正在播报回答
- **WHEN** 用户选择停止
- **THEN** 当前语音立即停止
- **AND** 文字回答保持可见

### Requirement: 基于状态的回答契约
回答 MUST 根据结构化状态使用不同表达：当前检测到时说明规范物品名称、确定位置和观测时间；当前未检测到时先说明未检测到，再说明最后出现位置与时间，最后单独陈列最多三个推测；身份不确定或无历史时必须明确说明限制。

#### Scenario: 返回当前位置
- **GIVEN** 查询目标状态为 `currently_detected`
- **WHEN** 系统生成回答
- **THEN** 回答使用“已检测到”等确定性措辞
- **AND** 包含唯一规范位置名称、相对位置描述和最新观测时间

#### Scenario: 返回最后位置和推测
- **GIVEN** 查询目标状态为 `not_currently_detected`
- **WHEN** 系统生成回答
- **THEN** 第一部分明确说明当前未检测到
- **AND** 第二部分说明最后确定位置和时间
- **AND** 第三部分以推测标签列出不超过三个候选位置

### Requirement: 回答必须受观测事实约束
系统 MUST 只把位置服务返回的结构化确定状态作为事实。语言模型不得把自身常识、用户问题暗示或候选推测改写为确定位置；模型超时、响应格式错误或不可用时，系统 MUST 使用确定性模板完成回答。

#### Scenario: 语言模型补造位置
- **GIVEN** 结构化结果只包含最后位置“书桌”和推测位置“抽屉”
- **WHEN** 语言模型草稿将“抽屉”描述成当前确定位置
- **THEN** 回答校验拒绝该草稿
- **AND** 系统使用结构化模板返回正确状态

#### Scenario: 语言模型超时
- **GIVEN** 物品位置结构化查询已成功但语言模型超过配置时限
- **WHEN** 后端组织回答
- **THEN** 使用确定性中文模板返回全部核心事实
- **AND** 查询不得仅因语言模型不可用而失败

### Requirement: 五秒查询响应目标
在验收环境中，当目录、位置记忆和查询服务均已预热且目标物品已存在时，从文字提交或语音转写完成到文字回答可见的时延，二十次连续查询中 MUST 至少十九次不超过五秒。语音播报准备不得阻塞文字回答显示。

#### Scenario: 十个物品的响应验收
- **GIVEN** 房间目录中有十个可查询的具体物品且系统已预热
- **WHEN** 测试者对这些物品执行二十次当前位置或最后位置查询
- **THEN** 至少十九次在五秒内显示完整文字回答
- **AND** 每次回答均包含与状态相符的核心字段

### Requirement: 回答证据入口
当当前或最后确定观测存在证据时，网页回答 MUST 提供查看证据的入口，并显示证据图片、目标标记和时间；没有证据时 MUST 明确说明证据不可用。

#### Scenario: 展开证据
- **GIVEN** 查询结果关联一张可用证据图片
- **WHEN** 用户点击“查看依据”
- **THEN** 页面展示对应图片、目标边界和观测时间
- **AND** 展示内容关联查询目标的 `object_id`
