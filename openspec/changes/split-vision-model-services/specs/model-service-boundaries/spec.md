## Purpose

为室内物品查找的视觉模型建立可独立部署和资源隔离的服务边界，使模型升级、故障和 GPU 资源变化不会破坏已有的查询事实和演示闭环。

## ADDED Requirements

### Requirement: 模型服务可独立运行
系统 MUST 将视觉编排、Florence、Grounding、SAM 和 Embedding 提供为可独立启动、停止和配置的内部服务。视觉编排服务 MUST 不要求 GPU；各模型服务 MUST 不承担物品、证据或用户查询事实的持久化写入。

#### Scenario: 单个模型服务不可用
- **GIVEN** 视觉编排服务和 API 均处于可用状态
- **WHEN** 某个模型服务未就绪或调用失败
- **THEN** 编排服务返回可区分的服务状态或降级结果，且 API 中既有的物品与证据记录不被修改

### Requirement: 服务健康状态可观测
每个模型服务和视觉编排服务 MUST 分别提供存活检查与就绪检查；就绪检查 MUST 反映模型或其 mock 适配器是否可接受推理请求。

#### Scenario: 模型尚未加载完成
- **GIVEN** Florence 服务进程已经启动但模型尚未可用
- **WHEN** 部署系统请求该服务的健康状态
- **THEN** 存活检查成功且就绪检查返回未就绪状态

### Requirement: 演示数据源可替换
视觉编排服务 MUST 支持使用与摄像头帧输入相同结果契约的本地 mock 数据源，并允许在不改变浏览器或 API 查询契约的情况下切换至真实模型服务。

#### Scenario: 未配置真实模型的本地演示
- **GIVEN** 所有真实视觉模型服务均未配置
- **WHEN** 摄像头 mock 帧进入视觉编排服务
- **THEN** 编排服务通过 mock 数据源生成标准观测并继续向 API 上报，使用户能够完成物品查询与画面标注闭环
