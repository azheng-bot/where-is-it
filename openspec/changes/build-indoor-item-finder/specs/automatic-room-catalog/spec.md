## Purpose

本能力用于在用户无需预先拍照登记的前提下，从单卧室摄像头画面自动建立可编辑的具体物品和空间位置目录，并通过稳定唯一标识与唯一规范名称避免同类物品和相似位置之间的语义混淆。

## ADDED Requirements

### Requirement: 无需预登记的自动发现
系统 MUST 从实时摄像头画面自动发现持续出现的候选物品，并在形成稳定观测后加入待确认或已跟踪目录，不得要求用户先拍摄登记照片才能开始使用。

#### Scenario: 自动形成初始目录
- **GIVEN** 单卧室摄像头可用且画面中有多个稳定可见的日常物品
- **WHEN** 系统完成初始环境扫描
- **THEN** 系统自动生成候选物品目录、名称和识别置信信息
- **AND** 用户无需逐件拍照或填写类别

#### Scenario: 不稳定候选不被直接确认为具体物品
- **GIVEN** 某个视觉候选只短暂出现或识别证据不足
- **WHEN** 自动发现流程处理该候选
- **THEN** 系统将其保持为待确认状态或忽略
- **AND** 不得以高确定性名称加入正式目录

### Requirement: 至少十个具体物品
系统 MUST 能够在一个房间目录中同时维护至少十个具体物品，而不是只维护十个抽象类别。

#### Scenario: 十个物品验收
- **GIVEN** 摄像头已稳定观察到十个可视觉区分的具体物品
- **WHEN** 用户打开物品目录
- **THEN** 目录中至少存在十条彼此独立的物品记录
- **AND** 每条记录可被单独查询和修改

### Requirement: 稳定且唯一的物品身份
每个正式物品 MUST 拥有房间范围内唯一、不可因重命名而改变的 `object_id`，并拥有房间范围内唯一的规范显示名称。所有观测、图片和查询结果 MUST 通过 `object_id` 关联，不得仅通过自然语言名称关联。

#### Scenario: 重命名不改变身份
- **GIVEN** 一个物品已经积累位置历史和证据图片
- **WHEN** 用户修改该物品的显示名称
- **THEN** 该物品的 `object_id` 保持不变
- **AND** 既有历史和证据仍关联到同一物品

#### Scenario: 名称冲突被消解
- **GIVEN** 新生成或用户输入的规范名称与已有物品按归一化规则相同
- **WHEN** 系统尝试保存该名称
- **THEN** 系统拒绝模糊名称或自动追加可理解的区分信息
- **AND** 最终保存的规范名称在房间内唯一

### Requirement: 同类别具体物品区分
系统 MUST 结合外观特征和时空连续性区分同类别的具体物品；在证据不足以区分时，系统 MUST 标记身份不确定，不得静默合并或任意选定其中一个身份。

#### Scenario: 两个水杯分别建档
- **GIVEN** 画面中持续出现外观可区分的黑色水杯和白色水杯
- **WHEN** 系统建立物品目录
- **THEN** 系统创建两个不同的 `object_id`
- **AND** 生成如“黑色水杯”和“白色水杯”的唯一名称

#### Scenario: 两个高度相似物品无法可靠区分
- **GIVEN** 两个同类物品在当前视角下无法获得足够的区分证据
- **WHEN** 系统尝试将新观测匹配到具体身份
- **THEN** 系统标记该匹配为不确定并保留候选关系
- **AND** 不得把不确定观测当作某一具体物品的确定位置

### Requirement: 自动生成可修正的物品名称
系统 MUST 根据可见类别、颜色、材质、形态或文字等证据自动生成尽可能具体的中文名称，并允许用户修改规范名称和添加查询别名。

#### Scenario: 系统自动命名
- **GIVEN** 系统首次稳定发现一个具体物品
- **WHEN** 可获得类别和至少一个可区分属性
- **THEN** 系统生成包含类别与区分属性的名称
- **AND** 在目录中标记该名称为系统生成

#### Scenario: 用户修正名称
- **GIVEN** 系统将某物品命名为“黑色小盒子”
- **WHEN** 用户将其改为“我的耳机盒”并添加别名“耳机”
- **THEN** 后续界面和回答使用“我的耳机盒”
- **AND** “耳机”可用于解析查询但不会替代唯一规范名称

### Requirement: 自动生成唯一空间位置
系统 MUST 从房间画面自动发现家具、承载面和语义区域，为每个正式位置创建不可因重命名而改变的唯一 `location_id`、房间内唯一的规范名称及可用于位置判断的空间区域。

#### Scenario: 自动建立位置目录
- **GIVEN** 画面中稳定可见床、书桌和床头柜
- **WHEN** 系统完成空间扫描
- **THEN** 系统分别建立具有不同 `location_id` 的位置记录
- **AND** 为其生成房间内唯一的中文规范名称

#### Scenario: 相似位置名称消歧
- **GIVEN** 房间中存在两个都可能被称作“床头柜”的区域
- **WHEN** 系统生成规范名称
- **THEN** 系统使用“床左侧床头柜”“床右侧床头柜”等空间属性消歧
- **AND** 不得保留两个相同的规范位置名称

### Requirement: 用户可修正位置目录
系统 MUST 允许用户修改位置名称和画面中的空间区域；修改后 `location_id` MUST 保持不变，历史记录 MUST 使用最新名称展示且保留发生时的原始名称快照用于审计。

#### Scenario: 修正自动区域
- **GIVEN** 系统生成的“书桌”区域包含了部分床面
- **WHEN** 用户在区域编辑器中调整边界并保存
- **THEN** 新观测按修正后的区域判断位置
- **AND** 既有事件继续关联原 `location_id`
